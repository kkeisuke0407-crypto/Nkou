## ファイル構成

```
ポートフォリオLP/
  build.mjs                  … src.html＋partials を組み立てて index.html を作る
  README.md                  … 使い方・LPの追加手順
  shared/
    portfolio.css            … 追加スタイル（c1-* は最小限）
    img/                     … 新LPだけで使う画像（競合校のCC写真）
    partials/                … 全LP共通のコンテンツ資産（N高詳細・クラーク詳細・第一学院詳細・生徒の声・高校生活・注意点・学費表・資料を見る理由・最終CTA・ヘッダー/フッター）
  CP01_王道ランキング/        … page.json＋src.html（骨格）→ index.html（生成物）
  CP02_その他ジャンル/fee/
  CP03_競合/DESIGN.md         … 設計のみ
  CP04_インテント/schooling/
```

CSS・JS・N高画像は `CORE01_記事LP/` のもの（parts.css・core01.css・main.js・assets/img/）をそのまま使う。

## 守ること

- デザインは mt-* パーツで組む。独自カードを作らない。c1-* を足すときは 02 のルールに従い、理由を IMPLEMENTATION の記録に残す。
- CP02・CP04は「検索ニーズへの答え」を FV の直後に置く。CP04に比較表・TOP3を機械的に足さない。
- ランキングは3校すべての詳細を作る。順位の根拠を書き、点数・星・架空の評価は作らない。
- 競合校の公式画像は使わない。口コミを創作しない。条件の違う金額を横並びにしない。
- 実質負担額には「※就学支援金の適用を受けた場合」を必ず添える。
- N高は「メンター」。表示コピーで「通信制高校」を多用しない。ネガティブな生徒像を作らない。
- CTA_URL は `CORE01_記事LP/main.js` の1カ所のまま。ASP URLに独自パラメータを付けない。Analyticsに ASP URL を送らない。
- GTM/GA4 の追加・CTA URLの設定・広告配信・新しいLPの追加は、指示があるまで行わない。
- 375px最優先：表は横スクロール＋左列固定、長文セルにしない、画像を無意味に大きくしない。

## LPを追加する手順

1. 同じ型のフォルダをコピー（例：`CP04_インテント/schooling/` → `CP04_インテント/online/`）。
2. `page.json` の slug・lpId・title・description を変える。
3. `src.html` の「KW専用」の部分（FV・答え・詳しい説明など）を書き換える。共通ブロックは `<!-- @include ... -->` のまま。
4. `node 案件_N高資料請求/ポートフォリオLP/build.mjs` で index.html を作り、375pxで確認。
5. 公開は main へのマージ時に workflow が `/pf/<slug>/` へ書き出す。

## 完成後チェック

- 見出しだけを追って内容が分かるか
- 広告KW → FV → 答え の距離が短いか（CP02・CP04）
- 比較表まで前置きが長くないか（CP01）
- 1位だけ長く、2位・3位が2行で終わっていないか
- 競合名がCP03のHTMLに1件も残っていないか（CP03を実装する場合）
